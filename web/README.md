# web: the mlsrag client

A Vite + React + TypeScript app (shadcn preset `b1Q5GC`, TanStack Router and Query) in front of
the mlsrag API. Pages: Docs, Models, Results, Interactive, Guide.

## Run

```bash
mlsrag serve --port 8000        # the API, from the checkout root
pnpm --dir web install
pnpm --dir web dev              # http://localhost:5173, /api is proxied to 127.0.0.1:8000
```

## Build and check

```bash
pnpm --dir web build            # type-checks, then writes web/dist/
pnpm --dir web lint
pnpm --dir web typecheck
pnpm --dir web format           # prettier
```

## Regenerate the API client

The typed client (`src/api/client.ts`, `openapi-fetch`) uses types generated from the committed
OpenAPI document. After the API changes:

```bash
pnpm --dir web gen:api          # ../rag/extensions/platform/openapi.json -> src/api/schema.d.ts
```

`src/routeTree.gen.ts` is generated by the router's Vite plugin on `dev` or `build`; commit it.

## Interactive mode

`/interactive` is a chat page. Pick a config (a preset from `GET /api/configs`, or edit any `RunConfig`
field under **Config → Advanced**; the controls are built from `/openapi.json`), then type a question or
record one with the microphone button. Each question is answered on its own (no conversation context):
text goes to `POST /api/query`, a recording (WebM, or MP4 on Safari) to `POST /api/query/audio`, where
whisper-1 transcribes it. Under each answer, **What ran** names the implementation and time of every
stage; **Full detail** shows the transcript, the evidence, the prompt, the span timeline, counters and cost.
An invalid config comes back as the API's 400 message in the chat.

The server answers one question at a time and a Qwen answer takes 35 to 90 seconds, so the page shows a
waiting timer and never retries on its own. Recording needs `https` or `localhost` and microphone permission.

Settings (gear icon, kept in `localStorage`): the default config for new chats, "confirm the transcript of a
voice question before showing its answer" (the API has no transcription-only call, so the answer is fetched
and held back until you accept the transcript, or edit it and ask again as text), and the admin token.

**History is on-device only.** Chats and messages, including each full API response and the recording, are
stored in this browser's IndexedDB (Dexie database `mlsrag`). The server stores nothing about users. Each
chat can be renamed, deleted or exported as JSON (recordings are left out); **Import** reads such a file back,
and **Clear all** deletes every chat after a confirmation.

## Results mode

Read-only views of the committed runs in `rag/extensions/results/` (from `GET /api/results...`). Every number
shown is the stored `metrics.json` or `queries.jsonl` value; tables print it in full, cards and charts round it.

| Route | What it shows | URL state |
|---|---|---|
| `/results` | runs (config, subset, queries, date, Recall@10, MRR@10, NDCG@10, ELM calls) and matrices | `q` search, `sel` ticked runs |
| `/results/compare?runs=a,b,c` | config fields that differ, then four charts: one metric family by run, latency by stage, a metric against cost (mean ELM calls per query or mean latency), a retrieval metric per query | `runs` (up to 6), `metric`, `x` (`calls` or `latency`) |
| `/results/<run_id>` | every metric of the run, the per-query table (sort by any column, filter by query id) | `sort`, `desc`, `filter` |
| `/results/<run_id>/<query_id>` | the answer, retrieval metrics, judge scores if stored, then the full detail: transcript, top-k records (text from `/api/records/{id}`), prompt, span timeline, counters, cost | none |

Each chart (`src/components/charts/`, Recharts) has a **Show table** button that swaps it for a table of the same
numbers. Remote calls served from the cache take about 1 ms and cost nothing, so they are not latency or cost
samples: such spans are marked `(cached)`, and a run with any cache hit shows `–` for latency and cost in the
comparison charts (the run page still lists its stored values). Per-query judge scores are not part of the trace, so the query page shows them only when
a trace carries a `judge` field.

## Layout

`src/routes/` pages (file-based routes), `src/components/` shared components (`ui/` from shadcn),
`src/api/` the client, `src/content/` the Markdown shown on Docs and Guide.
The admin token from the settings dialog is kept in `localStorage` and sent as `X-Admin-Token`.
